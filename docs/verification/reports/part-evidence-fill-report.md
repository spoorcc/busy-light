## What was not found (claims entered as source-missing or noted)

- **74LVC1G02 (U13):** no datasheet in the folder. Six claims `source-missing`, no number. The NOR gate is on the exclusive-step path.
- **2N7002 RDS(on) at VGS = 3.3 V:** the document gives 7.5 ohm max only at VGS = 5 V and 10 V. The ILIM select switches are driven from a 3.3 V output. The analysis script `ilim_steps.py` assumes 15 ohm; that stays an assumption.
- **2N7002 vendor:** the board value is generic. The only document is the Microchip one, supplied by the owner; limits of other vendors are not covered.
- **SN74AHCT1G125:** no Ioff or partial-power-down statement and no VIH/VOH below VCC = 4.5 V (searched for Ioff, "partial", "power-down"). Matches the earlier finding.
- **USBLC6-2:** no continuous voltage rating for the VBUS pin in Table 1; only VRM = 5.25 V (leakage test point) and VBR min 6 V. Whether VBUS up to 5.5 V is allowed is not stated.
- **ESP32-C3:** no absolute maximum voltage or current for a single GPIO in the module datasheet v2.2 or the chip datasheet v2.4 (only the power pins, the cumulative output current and VIH max = VDD + 0.3 V). A 5 V level on a GPIO is not covered by any stated limit. Two claims `source-missing`.
- **WS2812B:** no supply current per LED. The abs max supply (+3.5 to +5.3 V) conflicts with the condition of the electrical table (4.5 to 5.5 V) inside the same file. The file is not a manufacturer datasheet (see below).
- **TPS3840:** `tD(no cap) min` is not given (the delay-minimum equation 6 cannot be evaluated without an assumption; written in the claim notes). CT pin leakage is not given.
- **USB-C receptacle (J1):** no datasheet for the footprint's connector (GCT USB4085) and no USB Type-C specification (the document that names the pins). Only the contact list of a USB 2.0 receptacle and the 40 mohm contact-resistance requirement come from the USB-IF compliance document. Pin names and the VBUS current rating are `source-missing`.
- **Regulator (U8), TVS1/TVS2, tactile switch (SW1):** parts not chosen or no datasheet; every claim `source-missing`.
- **Resistors and capacitors:** no datasheet. The design values (0.1 percent ILIM resistors, C0G hold-off capacitors) are not datasheet facts; the claims state what must be shown. The Murata GRM31C5C1E474JE01 and GRM31C5C1H154JE02 downloads failed earlier (datasheets README).
- **LCSC and other identifiers:** none entered. No document in the folder carries one.
- **Not extracted:** values that exist only in figures or graphs; thermal and package-mechanical data beyond RθJA where noted; most dynamic characteristics (rise and fall times, typical curves); no `bbox` was entered.

Pin table against `full.net`: for TPS2553, 74LVC gates, 74AHCT1G125, 2N7002 and USBLC6-2P6 every netlist pin matches a datasheet pin by number and name.
Findings of the pin report:
- ESP32-C3-MINI-1 (U9): the schematic symbol identifies all 18 used pins by name (`GPIO0`, ...), not by pad number, so the pad numbers 5, 6, 8, 12 ... are not checked against the module's pad map. The unused NC pads are not in the symbol.
- TUSB321 (U1): six pins (`CC1`, `CC2`, `GND`, `PORT`, `VBUS_DET`, `VDD`) are identified by name; the other six use the datasheet numbers.
A PCB needs pad numbers, so the symbol of U9 and U1 needs numbered pins before the pad check is meaningful. This is a finding for the schematic, not a design change.

## Value-by-value comparison with the earlier reports

I did not diff all values. I compared the TPS3840, TPS2553, SN74LVC1G04 and buffer values listed in the earlier reports with what I read in the PDFs (thresholds, hysteresis, delay equations, IDD, VOL, VPOR, abs max, pin numbers, Ioff, VIH/VIL). I found no difference in that subset.
Not compared: the TPS3808 and TPS3839 negative-control values (those parts are not on the board and have no evidence file), and the sensitivity and sizing tables.

## What was not run

- **No independent verification:** nobody and no other agent has checked any claim, so the count of `verified` is 0. The mechanical check proves hash, page, quote presence and that each stored number occurs in the quote; it does not prove the correct column, variant or condition. Column assignment for single-number table rows was checked by the x position of the number for a sample (TPS2553, TUSB321, TPS3840, 74LVC1G11), not for every row.
- **No CI change:** the repository CI runs `pytest`, which validates the committed files against the schema and checks the format; the hash and quote checks need the PDFs and run only locally. `scripts/check_traceability.py` does not call the checker. The command is documented in `hw/evidence/README.md`.
- No analysis script in the spike worktree was changed or run; `README.md` of `hw/evidence` only describes how they would call `load_claim()`.
- No second source (other vendors' 74LVC or 2N7002 datasheets) was read.
- Figures and graphs were not read.
- The ADR has had no goldfish review. HW-012 and TC-212 are drafts and are not Approved.
- No compliance statement is made or implied.
